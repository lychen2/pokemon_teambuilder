# 优化清单与决策记录

基于 2026-09-14 的公开资料调研和当前实现评测。优先级含义：P0 为影响结论可信度的重点；P1 为常见构筑流程的直接收益；P2 为资料与扩展体验。工作量是粗略估计，不是交付承诺。

## 已实现并纳入验证

| 项目 | 依据 | 当前结果 |
|---|---|---|
| 具体速度线与同速提示 | Pikalytics、VGC Guide 的控速讨论 | 对照当前完整配置，支持双方顺风、空间、天气/场地、Mega、麻痹和速度等级 |
| 统一速度公式 | 规则一致性要求 | 复用 Champions calc；增加真实 Showdown 种子轻装、负等级和麻痹对照 |
| 构筑笔记 | Traylor 的团队理解步骤、两份世界赛队报 | 成员任务、首发/后排、胜利路线、困难对局和待验证假设模板，自动保存 |
| 指定位置替换 | Kelsch 对低选出成员的调整 | 编辑器中直接发起，其他成员及锁不变，预览后整组应用 |
| 命中与击杀概率分开 | Glick 对可控风险的讨论 | 显示基础命中率和计算前提，不把最高乱数写成必定击杀 |
| 更具体的推荐差异 | 实测发现单独显示伤害不能解释承伤改善 | 只列发生变化的伤害、击杀概率、承伤和速度信息 |
| 快速迭代规则 | 新赛季需求与实际打包验证 | 本地编译、类型表同步、候选校验、版本保留、迁移；编译运行时随 Linux 包附带 |

## P0：先提高分析的可信度

| ID | 明确任务与依据 | 验收方法 | 工作量 / 依赖 |
|---|---|---|---|
| P0-1 | 校准模拟策略先验。当前以种族值/属性/功能启发式给行动排序，尚不足以表现灭歌、复活、换人循环、目标免疫与资源时机；M-C 论坛和队报均显示这些行为会决定配置价值 | 固定引擎、对手和预算，比较现有策略、伤害驱动策略与支援策略；人工审阅失败对局；报告每类胜利条件的表现，而不只总胜率 | 5–10 天；依赖完整回放与情境用例 |
| P0-2 | 改进信息状态表示和树复用。当前深层状态非常具体，跨采样轨迹复用有限 | 报告节点访问分布、策略覆盖、同预算样本效率、隐藏信息不变性与独立种子成绩；任何状态压缩不得合并不同已知招式/道具信息 | 4–8 天；依赖 P0-1 基线 |
| P0-3 | 改进六选四路线与特殊支援评价。快速平均承伤/进攻矩阵会低估灭歌、复生祈祷、掩护和循环资源 | 构建带作者意图的真实队伍用例；比较实际选出及胜利条件；对同一支援配置移除关键队友应产生可解释变化 | 5–10 天；依赖角色知识和 P0-1 |
| P0-4 | 校准配置后验。当前新模型的道具复原略高，但特性与完整配置复原没有整体优势 | 按新时间窗口重新留出；报告 log loss、Brier、置信度分箱、配置复原和消融。当前留出集合只作为开发参照，不能反复调参后再当盲测 | 3–6 天；依赖新增独立样本 |
| P0-5 | 让缺配点观察贡献已知招式/道具证据，同时避免把未知字段补零。目前完整配置聚类排除了部分观察 | 在真实完整样本上主动遮蔽字段，评估流派分配和后验偏差；保留完整 medoid；不合法已知字段不进入当前配置证据 | 2–4 天；依赖分字段合法性校验 |
| P0-6 | 扩充机制矩阵与计算状态。重点覆盖多段命中次数分布、天气/场地争夺、低血量、换入后的能力状态、复活与特殊伤害依赖 | 每个新增场景逐档或逐状态对照 Showdown；展示条件；新规则导致差异必须可重现，不允许跳过失败 | 持续；按新规则差异排序 |

当前评测不能支持“新算法显著更强”的结论。P0 的目标是先获得可靠的证据与失败分类，而不是添加更多复杂算法名称或提高一个不可解释的综合分。

## P1：把构筑计划变成可复查的工作流

| ID | 明确任务与依据 | 验收方法 | 工作量 / 依赖 |
|---|---|---|---|
| P1-1 | 在笔记上增加结构化对局计划：对手六只、多个选出/首发、赢法、担忧和验证状态。来自 Traylor、Ceribelli 队报 | 用户能够保存两条不同路线，在保持队伍上下文的情况下打开对应伤害与速度；不自动伪造“最优”计划 | 2–4 天 |
| P1-2 | 添加轻量实战记录：实际选出、结果、关键失败原因、当时队伍版本和可选回放链接。记录“常用强势成员却很少选出” | 修改队伍后旧记录仍指向旧版本；样本量/缺失标签明确；不把训练记录当独立评测 | 3–5 天；隐私默认本地 |
| P1-3 | 速度目标与配点优化直接连通。现在已能看目标速度，但需手工填入自然速度阈值 | 点击对手速度线可生成一个带形态/条件的目标；自然速度和顺风/轻装后的速度不混用；显示同速和投资代价 | 2–3 天；需扩展 SpreadRequest 条件 |
| P1-4 | 保存多个条件模板并进行范围检验：对手不同流派、轻微削血、天气失去等 | 配点结果显示在哪些条件仍成立、在哪些条件失败，避免只对单份配置过拟合 | 3–5 天；依赖 P0-6 |
| P1-5 | 增加只影响记录的修订与计算修订区分。现在改名称/笔记也会触发分析过期 | 名称或笔记编辑不重算伤害、不丢弃有效建议；成员、字段锁、规则与数据变化仍严格使旧结果过期；并发保存不覆盖笔记 | 1–2 天；涉及版本绑定测试 |
| P1-6 | 增加来源意图与变体链：原作者、分享者、改动成员/招式、早期配点标记。来自两条 X 发布 | 原文链接可追溯；作者未提供的内容保持未知；不同配点不误合并；角色说明与统计字段分开 | 2–4 天；先手工确认，后辅助提取 |
| P1-7 | 基于计算条件呈现风险与替代方案，例如低命中招式、高反伤、对单成员依赖 | 展示基础命中与实际机制的区别；用户可比较可靠但较弱的替代路线；不直接把基础命中率当总胜率 | 3–6 天；依赖 P0-1/P0-6 |

## 尚未决定，保留在文档中的事项

- **更多外部统计源**：目前不替换用户指定共享表。引入 Pikalytics、MunchStats、LabMaus 或回放数据前，需要核验可持续获取方式、统计口径、规则覆盖和许可；LabMaus 正文仍未成功读取。
- **个性化偏好**：可考虑节奏偏好、操作熟练度和可接受风险，但不能在没有用户记录时推断偏好。建议先支持可编辑的软权重和笔记。
- **更高成本训练**：优先在本地复评闭环中校准策略；是否训练强化学习策略、使用 GPU 或引入额外运行环境，取决于基线收益与可复现成本。
- **公开队表/BO3 主流程**：模拟接口已有公开队表选项；产品默认仍为 M-C BO1 封闭队表。BO3 的跨局信息学习需要单独模型，不把单局重复三次当作完整实现。
- **自动理解 RMT**：可以辅助提取，但作者意图、效果评价、实测条件须附原文依据并允许人工纠正；不将生成的解释混入作者原话。
- **发布渠道与其他系统**：当前仅交付本地 Linux x86-64 包；签名、公网自动升级、云端同步、Windows/macOS 分发尚未决定。

## 迭代顺序

先固定当前版本、保留真实失败案例和完整评测结果；并行推进的业务方向以 P0-1/P0-4 和 P1-1/P1-2 为主。只有在新的独立时间窗口和多种策略下看到稳定收益，才调整默认推荐权重。规则更新则始终沿候选快照、机制验证和迁移路径进行。
