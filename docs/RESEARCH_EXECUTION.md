# 调研功能实施与验收

调研功能沿用桌面工作台、规则快照、配置模型与后台线程，贯通构筑、计算、证据和复盘。原始依据保留在 [RESEARCH.md](RESEARCH.md)，19 项实现状态见 [OPTIMIZATION_TODOS.md](OPTIMIZATION_TODOS.md)，真实验证结果见 [VALIDATION.md](VALIDATION.md)。

## 实施顺序

1. **记录与版本基础**（P1-1、P1-2、P1-5、P1-6）：区分计算修订与记录修订，持久化结构化对局计划、实战记录和来源说明；记录始终指向当时的完整队伍。
2. **统一计算条件**（P0-6、P1-3、P1-4、P1-7）：扩展同一 BattleField 与伤害适配器；速度目标直接进入配点，条件模板与范围验证共享同一请求格式；从实际计算解释风险。
3. **配置与构筑知识**（P0-3、P0-4、P0-5、P2-2、P2-3）：已知字段证据、校准诊断、版本化机制角色、六选四路线与角色缺口候选，保持真实 medoid 与合法性。
4. **模拟策略与证据**（P0-1、P0-2）：以可见信息和预先分配的计算预算比较策略；完整对局记录、树访问统计、支援/轮转/特殊赢法场景与独立种子复评。
5. **数据与维护**（P2-1、P2-5、P2-6）：环境关联的来源注册表、独立资料与回放导入、来源口径、存储占用与用户选择的维护操作。
6. **完整体验与交付**（P2-4）：键盘、缩放、窄窗、中文输入和可访问性检验；实际 Linux 安装包复验、许可证、使用与验证文档。

## 决策边界

- 不将未发表的新样本、无法访问的网页或没有实际设备完成的手测写成通过；评测工具完成与经验优势得到证明分开报告。
- 外部统计源通过注册表记录获取方式、采样范围与许可；不能确认口径的资料保留为研究证据，不冒充排位频率。
- 偏好由用户填写软权重。RMT 提取保存原文证据与人工确认，不把生成解释当作者原话。
- BO3、强化学习训练、公网升级、云同步与其他平台在原调研中是未决定事项；本地资源约束和证据不足不通过增加未经验证的依赖来掩盖。先完成明确条目的通用接口、数据与实测。

## 状态

六批实现均已落入共享工作台与后台服务。应用 0.3.0 / 算法 mc-1.4.0 的核心回归为 8 个文件、57 项，分文件各设 60 秒硬超时后全部通过。运行目录的 15 项普通桌面流程及独立规则更新检查通过，真实系统输入法独立执行。普通桌面用例限时 60 秒；规则更新包含完整编译、聚类、校准、激活与迁移，单独限时 120 秒。之前的整套核心超时和规则端到端超时均保留日志，无自动重试。真实配置变体贯穿浏览、后验与搜索；旧模型升级、自定义语料重建和取消均已实际验证。规则与数据候选在实际成品内再次验证，发布文件、检查记录及算法基线由验收文档统一索引。

本版使用按完整形态匹配的 Champions 图片，覆盖雌雄、地区形态与 Mega；样本不足时提供通过当前规则校验的历史配置，并将来源赛季与当前频率分开。统一的选出和 Mega 评价用于搜索、快速对照及模拟预览。规则重建复用同一快照、角色信息和聚类中间结果，在完整语料上与优化前持久化模型逐项相同；没有减少样本或跳过校准。性能和方法比较分别记录，不将提速解释为实战提升。

算法已提供可重复对照、受控遮蔽、消融和逐场回放，但功能完成不代表开发集上的整体优势，更不代表真实排位水平。新的外部盲测、专家对局复盘、人工读屏和物理多屏没有被列为已通过。
