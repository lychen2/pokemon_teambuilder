# 构筑机制与计算范围

应用 0.3.1 / 算法 mc-1.6.0 将机制入口划分为八类、62 项。目录顺序按构筑用途组织，不按某个热门物种的特性选取分类。

| 类别 | 主要入口 |
|---|---|
| 速度与行动顺序 | 顺风、戏法空间、降速、麻痹、延后与您先请 |
| 天气 | 晴、雨、沙、雪、天气效果压制 |
| 场地 | 青草、精神、电气、薄雾；场地种子作为条件项 |
| 保护与掩护 | 守住、重定向、广域防守、快速防守、先制阻断、双墙、极光幕、友情防守、异常保护 |
| 干扰与反制 | 击掌奇袭、威吓、削弱输出、催眠、灼伤、挑衅、再来一次、定身法、封印、反强化、道具与特性干扰、强制换人 |
| 进攻与强化 | 范围与先制进攻、物理/特殊/复合强化、帮助、队友强化、穿过守住、拆墙 |
| 轮转与续航 | 轮转招式、再生力、自身回复、队友回复、款待、复生祈祷 |
| 终局路线 | 灭亡之歌、限制换人、持续消耗、同命与定量交换 |

轻装、天气加速、变化招式先制、气腰与满血防守、抗威吓等出现在各自用途下的「特性与道具条件」，不单独占据首页主要分类。没有声称这些条件不重要；它们的价值需要配置、队友与实际战斗状态共同成立。

## 从机制找到配置

构筑素材中的「筛选功能」支持类别浏览，以及机制、招式、特性和道具的中英文检索。数字表示具有匹配完整配置的物种数，包括按当前规则校验过的历史资料。零配置机制仍显示，但不能据此选出不存在的配置。

选择机制后，物种列表、流派概览、真实变体和历史开关始终保留同一条件。流派代表不匹配时展示该流派中真实匹配的变体，原配点、招式及来源保持不变。不会因为该物种的另一个配置带有广域防守，就把不带广域防守的配置加入筛选结果。

Mega 检索使用当前环境的形态与进化石对应表。喷火龙 Y 的日照、Mega 耿鬼的踩影标注「仅 Mega 后获得」。初始特性不被改写；进化时机与每场唯一 Mega 仍由战斗上下文处理。

## 三种证据不可互换

- **配置识别**：配置拥有相关招式、特性、道具或指定 Mega 条件。不是强度或胜率结论。
- **有条件精算**：图谱逐项列出伤害、速度或命中风险页实际支持的条件。例如双墙可精算；极光幕目前仍由回合执行，没有假装进入相同的快速计算。
- **真实回合**：Showdown 执行实际规则。策略是否选择并有效利用该机制，需核对回放；没有给整个目录统一打上「战术已验证」标记。

新增机制关系涵盖四种天气和场地、雪天下建立极光幕、雨天命中、场地阻挡己方先制或催眠、掩护与关键行动、广防与队友范围误伤、回复、轮转、黑雾清除己方强化等。说明均保留成立条件。携带设置天气的招式不会让快速分析直接假定天气已经建立。

## 推荐和聚类的处理

共享机制目录位于 `packages/core/analysis/mechanisms.ts`。机制细目、构筑用途和条件特性分层维护；不依赖渲染器或 Node API。

- 功能标签按实际作用去重。顺风、麻痹和降速可共用「控速」用途；轻装由特性与道具条件描述，本身不增加功能覆盖分。
- 候选初筛的缺口收益按八个用途组计算，不按62个细目累加或逐项占用候选名额。指定保留的真实变体仍优先保留。
- 候选预算按基础物种作递减分配：先保留相关性，再降低重复保留同种变体的边际收益。没有固定每物种一份或两份的限制，也不会让同一物种45份配置挤掉其他补位选择。真实沙暴核心的无解回归用例用于核对可补齐性。
- 搭档说明使用独立资源键归并。同一个行动窗口、复活资源或屏障不随描述条数或受益成员数量重复计分。
- 天气与场地已经进入数值对照，不再因为多写一条相关说明给最终评分额外奖励。其依赖关系仍用于寻找候选。
- 快速支援分仍是可见的启发式，数值权重未重新调优；不能据功能覆盖扩大宣称推荐更强。角色距离改变后用固定原始语料重建模型，并更新算法与缓存版本。

## 后续规则迭代

可用招式、特性与道具每次由当前 Showdown 环境检查，知识版本同时绑定环境和目录内容。禁用广域防守的规则变更已加入回归；不会沿用旧环境的可用标记。配置筛选只使用当前环境已校验的真实资料。

同一机制的名单或学习表变化沿既有快照更新流程处理。新机制或新语义需要更新单一目录、必要的战斗适配和相应用例，不能仅凭名字存在就宣称已支持其快速收益评估。

`tests/mechanisms.test.ts` 核对真实数据引用、机制分类、规则变化、Mega 对应和资源去重；`tests/desktop/mechanisms.spec.ts` 覆盖筛选贯穿、历史开关、输入焦点和机制图谱。`tools/strategy-benchmark.ts --mechanisms` 另外选取14类常见机制队伍进行三种策略的回合对照，保留原六类评测以便同口径比较。
